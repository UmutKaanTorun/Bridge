# Köprü v0.1 — Tasarım

- **Tarih:** 2026-11-20
- **Durum:** Onaylandı (2026-11-20)
- **Bağlam:** "CrossOver Alternatifi: Mimari ve Yol Haritası" planının Faz 1'i. Faz 0'da CrossOver 26.3.0 açık kaynak kodundan derlenen Wine 11.0 + DXMT 0.80 motoru (`~/WineEngines/WineCX26.3.0-DXMT0.80`) Steam ve bir Unity oyunuyla doğrulandı. Kapalı beta Ocak 2027'de başlıyor; v0.1 o betanın iskeleti.

## 1. Amaç

Faz 0'daki kabuk betiklerini (`oyun26.sh`, `steam26.sh`, `steam-kur.sh`) CrossOver modelinde çalışan bir Mac uygulamasına dönüştürmek: tarifle tek tık kurulum, tarifsiz ("listede olmayan") kurulum, bottle ve program yönetimi.

### Başarı ölçütleri

v0.1 bu Mac'te (M3, macOS 26.6) şunları yaptığında biter:

1. Köprü (`Kopru.app`) açılır, motoru bulur; motor ya da Rosetta yoksa ne yapılacağını söyler.
2. "Listede olmayan program" yoluyla Notepad++ kurulur, programlar ızgarasında görünür, çift tıklayınca açılır.
3. Steam tarifi (ev ağında) Steam'i kurar; giriş penceresi siyah değil, düzgün açılır.
4. `~/WineBottles/faz0-oyun26` içe aktarılır; Steam ve onun içinden Thief Simulator 2: Prologue Köprü'den açılır.
5. `KopruCore` birim testleri geçer.

## 3. Mimari

```
Kopru.app — görünen adı Köprü (SwiftUI)
└─ KopruCore (yerel Swift paketi, arayüzden bağımsız, birim testli)
   ├─ Engine          motor yolu + Wine ortam değişkenleri
   ├─ BottleStore     bottle oluştur / listele / yeniden adlandır / sil / içe aktar
   ├─ WineRunner      wine süreçlerini başlatır, günlüğe yazar, bottle'ı durdurur
   ├─ RecipeCatalog   uygulama içindeki JSON tarifleri okur, arar
   ├─ RecipeInstaller tarif adımlarını sırayla uygular, ilerleme bildirir
   └─ ProgramScanner  Başlat menüsü kısayollarından program listesi çıkarır
```

Her birim tek iş yapar ve diğerlerine yalnızca açık arayüzlerle bağlanır. Arayüz katmanı `KopruCore`'u bir `@Observable` uygulama modeli (`AppModel`) üzerinden kullanır; Wine ile doğrudan konuşmaz.

### 3.1 Engine

- `Engine.locate()` motoru şu sırayla arar: `Bundle.main.resourceURL/Motor` → `KOPRU_MOTOR` ortam değişkeni → (yalnızca Debug) `~/WineEngines/WineCX26.3.0-DXMT0.80`. Bulamazsa `EngineError.notFound` döner.
- `bin/wine`, `bin/wineserver` yollarını ve bir bottle için ortam değişkenlerini verir. `oyun26.sh`'in karşılığı:
  - `WINEPREFIX` = bottle klasörü
  - `DYLD_FALLBACK_LIBRARY_PATH` = `<motor>/lib`
  - `WINEMSYNC` = bottle ayarından (`1`/`0`)
  - `MVK_CONFIG_LOG_LEVEL=0`, `WINEDEBUG=-all`
  - FPS göstergesi açıksa `MTL_HUD_ENABLED=1`
  - Bottle ayarında `wined3dPrograms` varsa `KOPRU_WINED3D_EXE` (virgülle ayrılmış exe adları; 2026-11-21, [Rockstar grafik spec'i](2026-11-21-rockstar-grafik-motoru-design.md))
- Rosetta denetimi: `/Library/Apple/usr/libexec/oah/libRosettaRuntime` yoksa `EngineError.rosettaMissing`.
- Release derlemesinde bir derleme adımı motoru `include/` olmadan `Contents/Resources/Motor`'a kopyalar (~670 MB). `orijinal-grafik/` (3 MB) 2026-11-21'den beri pakette: program başına wined3d onu kullanıyor.

### 3.2 Disk düzeni

```
~/Library/Application Support/Kopru/
  Bottles/<klasör-adı>/        ← WINEPREFIX'in kendisi (drive_c, dosdevices, *.reg)
      kopru.json               ← Köprü'ye ait bottle bilgisi
  Downloads/                   ← indirilen kurulum dosyaları (önbellek)
~/Library/Logs/Kopru/<klasör-adı>.log
```

Klasör adı, görünen addan ASCII'ye çevrilerek türetilir ("Oyunlarım" → `Oyunlarim`); çakışırsa sonuna sayı eklenir. Görünen ad `kopru.json`'da durur.

`kopru.json`:

```json
{
  "schema": 1,
  "name": "Steam",
  "createdAt": "2026-11-20T18:00:00Z",
  "recipeId": "steam",
  "settings": {
    "msync": true,
    "virtualDesktop": { "mode": "auto" },
    "fpsHud": false
  },
  "pinnedPrograms": [],
  "hiddenShortcuts": []
}
```

- `virtualDesktop.mode`: `off` | `auto` (ana ekranın görünür alanı − 40 px) | `fixed` (`width`, `height` ile).
- `pinnedPrograms`: kullanıcının "Program Çalıştır…" ile seçip sabitlediği exe'ler (`name`, `windowsPath`, `arguments`).
- `hiddenShortcuts`: kullanıcının "Listeden kaldır" dediği kısayollar (Başlat menüsüne göre göreli yol).

### 3.3 Tarif formatı

Tarifler uygulamanın içinde `Resources/Recipes/<id>.json`; tarife ait ek dosyalar `Resources/RecipeFiles/<id>/`. v0.1'de tek tarif var: Steam.

```json
{
  "schema": 1,
  "id": "steam",
  "name": "Steam",
  "summary": "Valve'ın oyun mağazası ve başlatıcısı",
  "category": "game",
  "rating": "works",
  "bottle": {
    "defaultName": "Steam",
    "settings": { "msync": true, "virtualDesktop": { "mode": "auto" }, "fpsHud": false }
  },
  "installer": {
    "url": "https://cdn.cloudflare.steamstatic.com/client/installer/SteamSetup.exe",
    "sha256": null,
    "fileName": "SteamSetup.exe",
    "arguments": ["/S"]
  },
  "afterInstall": [
    { "action": "registry", "key": "HKCU\\Software\\Wine\\DllOverrides",
      "name": "gameoverlayrenderer64", "value": "" }
  ],
  "beforeLaunch": [
    { "action": "steamWebHelperProxy" }
  ],
  "launch": {
    "name": "Steam",
    "windowsPath": "C:\\Program Files (x86)\\Steam\\steam.exe",
    "arguments": ["-noverifyfiles", "-no-cef-sandbox"],
    "shutdownArguments": ["-shutdown"]
  },
  "detect": ["drive_c/Program Files (x86)/Steam/steam.exe"],
  "hideShortcuts": ["Steam/Steam.lnk"]
}
```

- `sha256` doluysa indirilen dosya doğrulanır, tutmazsa kurulum durur. Steam'in kurulum dosyası zaman zaman değiştiği için bu tarifte boş; yalnızca HTTPS'e güvenilir.
- Eylemler (v0.1'de yalnızca bunlar):
  - `registry`: `wine reg add` ile değer yazar.
  - `steamWebHelperProxy`: Swift'te yazılı özel eylem. `Steam/bin/cef/cef.win*/steamwebhelper.exe` 500 KB'tan büyükse (yani gerçek Steam dosyasıysa) `steamwebhelper_gercek.exe` olarak yeniden adlandırır, aracı exe'yi (`RecipeFiles/steam/steamwebhelper.exe`) yerine kopyalar. Steam güncellemesi aracıyı sildiğinde bir sonraki açılışta tekrar yerleştirilir.
- `gameoverlayrenderer64` kapatması Faz 0'da oyun exe'si başına yapılmıştı; burada bottle geneline uygulanır. Elle testte doğrulanacak; sorun çıkarsa oyun başına ayara dönülür.
- `detect`: içe aktarılan bir bottle'da bu dosya varsa bottle'a `recipeId` atanır.
- `hideShortcuts`: tarifin kendi başlatıcısı varken Başlat menüsündeki aynı programın kısayolu gizlenir (yoksa Steam aracı ve seçenekler atlanarak açılırdı).
- Aracı exe'nin kaynağı (`~/WineBuild/steamwebhelper-araci/araci.c`) depoya `Tools/steamwebhelper-araci/` altında alınır; derlenmiş exe `RecipeFiles/steam/`'e konur.

### 3.4 ProgramScanner

- `drive_c/ProgramData/Microsoft/Windows/Start Menu/Programs/**` ve `drive_c/users/*/AppData/Roaming/Microsoft/Windows/Start Menu/Programs/**` altındaki `.lnk` kısayolları ve `.url` Steam kısayolları taranır. Aynı göreli yol iki yerde de varsa bir kez alınır. (CrossOver motorunda Wine kullanıcısının adı `crossover`.)
- `.url` dosyalarından yalnızca `URL=steam://…` olanlar alınır (Steam oyunları, ör. `Steam/Thief Simulator 2 Prologue.url`). Bottle'da Steam tarifi varsa bu kısayollar tarifin başlatıcısıyla açılır: `steam.exe -noverifyfiles -no-cef-sandbox steam://rungameid/…` (aracı ve seçenekler atlanmasın diye). Tarif yoksa `start /wait /unix` ile.
- Adında "Uninstall", "Kaldır", "Readme", "Benioku", "Yardım", "Help", "Kılavuz", "Manual" geçen kısayollar ve `hiddenShortcuts`/`hideShortcuts` listesindekiler elenir.
- Kısayol açmak için `.lnk` ayrıştırılmaz: `wine start /wait /unix <kısayol.lnk>` (`/wait` sayesinde süreç program kapanana kadar yaşar; çalışıyor bilgisi ve "hemen kapandı" denetimi buna dayanır).
- Ekranda gösterilen liste = tarif başlatıcısı (varsa) + sabitlenmiş programlar + taranan kısayollar. Tarama her bottle gösterildiğinde yeniden yapılır (ucuz), böylece geç biten kurulumlar da listeye düşer.

### 3.5 WineRunner

- Programı `Process` ile başlatır; stdout/stderr bottle'ın günlük dosyasına eklenir.
- Sanal masaüstü açıksa komut `wine explorer /desktop=Kopru-<klasör-adı>,<G>x<Y> <komut…>` biçimine sarılır.
- Açılan programın süreci 5 saniye içinde sıfırdan farklı kodla biterse "program hemen kapandı" olayı yayınlanır.
- **Durdur:** tarifte `shutdownArguments` varsa önce o çalıştırılır, 10 saniye beklenir; ardından `wineserver -k`.
- Bottle'ın çalışıp çalışmadığı, Köprü'nün başlattığı ve henüz bitmemiş süreçlerden anlaşılır.

## 4. Akışlar

### 4.1 Tarifle kurulum

1. Kullanıcı Kur penceresinde tarifi seçer, bottle adını onaylar.
2. **Bottle hazırlanıyor:** klasör açılır, `wineboot --init`, `kopru.json` yazılır (tarifin ayarlarıyla).
3. **İndiriliyor:** `Downloads/`'a (yüzdeyle); `sha256` varsa doğrulanır. Önbellekte geçerli dosya varsa tekrar indirilmez.
4. **Kuruluyor:** kurulum dosyası `arguments` ile çalıştırılır, süreç bitene kadar beklenir.
5. **Ayarlanıyor:** `afterInstall` eylemleri.
6. Bitti; bottle seçilir, program ızgarada görünür.

Her adım ilerleme ekranında işaretlenir. Bir adım başarısız olursa ekran hangi adımda kalındığını, kısa bir açıklama ve "Günlüğü göster" düğmesini gösterir; kullanıcı yarım bottle'ı silebilir ya da tutabilir.

### 4.2 Listede olmayan program

1. Kullanıcı `.exe`/`.msi` seçer (ya da ana pencereye sürükler).
2. Yeni bottle (adı dosya adından önerilir) ya da mevcut bir bottle seçilir.
3. Yeni bottle ise hazırlanır (4.1/2).
4. `.exe` → `wine <dosya>`, `.msi` → `wine msiexec /i <dosya>`; Windows kurulum penceresi açılır, kullanıcı kurulumu kendisi bitirir.
5. Kurulum süreci bitince tarama yapılır; bulunan programlar ızgarada görünür.

### 4.3 Programı açma

Çift tık → `beforeLaunch` eylemleri (tarifliyse) → WineRunner ile başlatma. Tarif başlatıcısı `windowsPath` + `arguments` ile, kısayollar `start /wait /unix` ile, sabitlenmişler `windowsPath` ile açılır.

### 4.4 Var olan bottle'ı içe aktarma

1. Kullanıcı bir klasör seçer; içinde `system.reg` ve `drive_c` yoksa "Bu bir Wine bottle'ı değil" denir.
2. Ad sorulur (öneri: klasör adı). Pencerede "Klasör Köprü'nün bottle klasörüne **taşınır**; eski yolu kullanan betikler (ör. `steam26.sh`) onu artık bulamaz" uyarısı görünür.
3. Klasör `Bottles/`'a taşınır (aynı diskte anında), `kopru.json` yazılır (varsayılan ayarlar: MSync açık, sanal masaüstü kapalı).
4. Tariflerin `detect` dosyaları denetlenir; eşleşen olursa `recipeId` ve tarifin bottle ayarları atanır.

### 4.5 Bottle ayarları

MSync (aç/kapa), sanal masaüstü (kapalı / ekrana göre / elle boyut), FPS göstergesi, "Windows Ayarları" (`winecfg`), "C: Sürücüsünü Aç" (Finder), "Bottle'ı Sil" (Çöp Kutusu'na). Bottle çalışırken MSync değiştirilecekse önce "Bottle durdurulacak" onayı alınır ve bottle durdurulur; aynı bottle'da farklı MSync ayarıyla başlayan süreçler sessizce bozuluyor (Faz 0 bulgusu).

## 5. Ekranlar

- **Ana pencere** (`NavigationSplitView`): solda bottle listesi ve altında "+" (boş bottle / bottle içe aktar), sağda seçili bottle'ın program ızgarası (exe'deki ya da kısayoldaki gerçek simge + ad; okunamazsa genel simge — 2026-11-20'de v0.1'e alındı). Çift tık açar; sağ tık: Aç, Finder'da Göster, Listeden Kaldır. Araç çubuğu: **Kur**, **C: Sürücüsü**, **Program Çalıştır…**, **Durdur**, **Ayarlar**. `.exe`/`.msi` sürükle-bırak → 4.2.
- **Kur penceresi:** yerini Program kur sayfasına bıraktı; bkz. [2026-11-20-kur-ekrani-design.md](2026-11-20-kur-ekrani-design.md).
- **Bottle ayarları** (sheet): 4.5.
- **İlk açılış uyarıları:** motor yok / Rosetta yok.

## 7. Testler

- **Birim testleri (`swift test`, KopruCore):** tarif JSON'u çözümleme; ortam değişkeni üretimi; `kopru.json` okuma/yazma; ad → ASCII klasör adı; kısayol tarama ve eleme (sahte klasör ağacı); `steamWebHelperProxy` (sahte dosyalarla: büyük dosya yeniden adlandırılır, aracı yerleşir, ikinci çalışmada bir şey değişmez); içe aktarma doğrulaması ve `detect` eşleşmesi; sanal masaüstü komut sarmalama.
- **Motor entegrasyon testi** (ayrı, yavaş, `KOPRU_ENTEGRASYON=1` ile): geçici klasörde boş bottle oluştur, `wine cmd /c ver` çalıştır, çıktıda Windows sürümü görünür.
- **Elle test:** Başarı ölçütleri 1–4. Notepad++ kurulum dosyası `~/WineBottles/indirilenler/notepadpp/`'de; Steam tarifi ev ağında.

## 8. v0.1'e girmeyenler

Uyumluluk puanlı çevrimiçi tarif veritabanı; .NET / Visual C++ gibi bağımlılık kurucuları; bottle başına grafik motoru seçimi (DXMT motora gömülü); Dock ve Programlar klasörü kısayolları; Sparkle; Paddle / lisans; Developer ID imzası, Hardened Runtime ve notarizasyon; İngilizce arayüz; birden çok motor sürümü.

## 9. Riskler ve açık noktalar

- **Steam aracısı Chromium sandbox'ını kapatıyor** (`--single-process`, `-no-cef-sandbox`). Ürün riski; kalıcı çözüm Wine'ın Mac sürücüsünde süreçler arası çizim. Faz 0 notunda bunun Wine ~11.13'te düzeltildiği söyleniyor, doğrulanmadı.
- **Ofis ağı** Steam'e TLS denetimi yapıyor; Steam tarifi yalnızca ev ağında test edilebilir. İçe aktarma bu yüzden v0.1'de.
- **Genel `gameoverlayrenderer64` kapatması** test edilmedi (3.3).
- **Yerel imza:** v0.1 yalnızca bu Mac'te çalışır; başka Mac'e verilmeden önce Developer ID gerekir (Apple Developer Program, yıllık 99 $).
- **Rosetta** macOS 28 (sonbahar 2027) ile büyük ölçüde kalkıyor; ARM64 motoru ayrı bir iş kolu.
